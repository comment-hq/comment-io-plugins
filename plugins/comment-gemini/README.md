# Comment.io for Gemini CLI — preparation only

This extension points to the current public remote MCP endpoint `https://comment.io/mcp`, documented as exposing one `run` tool. It is **not ready for authenticated installation or the Gemini Extension Gallery**: Comment.io requires a public HTTPS OAuth Client ID Metadata Document (CIMD), and this package has no verified client identity. Its manifest is valid for local layout inspection, not proof of a working connection. The repository's existing production publication remains pinned to alpha; reachability of this endpoint does not establish release status.

Before a connection test, the owner must provide an existing reachable HTTPS CIMD URL whose `redirect_uris` includes the exact local callback used by Gemini. Add that URL as `mcpServers.comment-io.oauth.clientId` in the extension manifest and set `oauth.redirectUri` to its registered callback. [Comment.io's authentication contract](https://comment.io/auth.md) requires a public client with no secret, no dynamic registration and no scopes; the generic MCP guide assumes a prepared client. Explicit `/mcp auth comment-io` uses the configured ID; current Gemini CLI automatic authentication after a 401 may drop the ID and fail because Comment.io does not offer dynamic client registration. Do not treat a successful manifest load as authentication.

The gallery requires a public repository or release archive with `gemini-extension.json` at its **absolute root**, plus the `gemini-cli-extension` GitHub topic. This package is in a subdirectory, so this repository is not gallery-eligible as-is. Choose and verify a release-root arrangement before proposing a topic, release, or listing.

## Evidence and compatibility gate

Observed on October 8, 2026: the manifest parses as JSON and references `https://comment.io/mcp`; an unauthenticated MCP `initialize` POST returned HTTP 401 with resource metadata, and the authorization-server metadata advertised CIMD (`client_id_metadata_document_supported: true`) without a registration endpoint. These checks do not demonstrate an authenticated connection. No hosted client metadata URL was identified. The following host checks have **not** run:

1. Verify the actual CIMD is served on HTTPS port 443 without redirects, names its own URL as `client_id`, and lists Gemini's exact local `redirect_uri`. Compare that URI with the configured `oauth.redirectUri` and confirm Comment.io's discovered authorization server advertises CIMD and no registration endpoint.
2. On a machine with a local browser and only an existing disposable workspace/agent, link this directory with `gemini extensions link plugins/comment-gemini` (use its absolute path if needed), restart Gemini, and confirm `/extensions list` loads the context and `/mcp` shows the intended endpoint. Trigger `/mcp auth comment-io` explicitly. Record browser approval and callback, not tokens. Abort if Gemini tries dynamic registration or redirects to a different client.
3. After consent, confirm `/mcp` reports connected and exactly `run`, invoke `run` with `help`, and check it starts `You are AGENT in workspace WORKSPACE.` Repeat after token expiry/refresh and reconnect; test revoked access. Read-only commands suffice. Dispose of the test agent/grant using the existing fixture's cleanup procedure.
4. Verify a proposed release archive has `gemini-extension.json` at its archive root and can install from that archive; a subdirectory of this repository is not a gallery root. Only then consider topic addition and gallery eligibility. No gallery action is part of this package.

See [MCP setup](https://comment.io/llms/mcp.md) and [authentication](https://comment.io/auth.md). A human workspace member chooses and approves the agent in the browser.
