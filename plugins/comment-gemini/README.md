# Comment.io for Gemini CLI — preparation only

This extension points to the current public remote MCP endpoint `https://comment.io/mcp`, documented as exposing one `run` tool. Its manifest can be installed locally, but authenticated tool use has not been verified in Gemini. The repository's existing production publication remains pinned to alpha; reachability of this endpoint does not establish release status.

[Comment.io's authentication contract](https://comment.io/auth.md) now offers dynamic client registration (DCR) for public clients and HTTPS Client ID Metadata Documents (CIMD), with no scopes or client secret. Current Gemini CLI source can discover DCR after an MCP 401 and retain its ID for token refresh. Explicit `/mcp auth comment-io` can also use DCR; with a configured CIMD `clientId`, that explicit path skips DCR while the automatic 401 path may not preserve that ID. Registration grants no workspace access: a human must approve an agent in the browser. No registration or grant was performed for this package.

The gallery requires a public repository or release archive with `gemini-extension.json` at its **absolute root**, plus the `gemini-cli-extension` GitHub topic. This package is in a subdirectory, so this repository is not gallery-eligible as-is. After committing the package, run `bash plugins/comment-gemini/package-release.sh comment-gemini.tar.gz` from the repository root. It archives the committed Gemini files at the archive root without the other plugins. Inspect and test that archive before any release or topic change. No release or topic change is part of this draft.

## Evidence and compatibility gate

Observed on October 9, 2026: an unauthenticated MCP `initialize` POST returned HTTP 401 with resource metadata; the authorization-server metadata advertised CIMD and `registration_endpoint: https://comment.io/oauth/register`. Gemini CLI 0.63.0 installed this directory and, separately, an extracted archive with the manifest at its root in isolated homes; `extensions list` showed the context file and `comment-io` MCP configuration. These checks do not demonstrate an authenticated connection or prove GitHub Release discovery. The following grant-dependent checks have **not** run:

1. With approval for disposable registration and a human-approved fixture, connect using Gemini's automatic 401 flow or `/mcp auth comment-io`. Record DCR, browser consent and callback without tokens. If choosing CIMD instead, verify its HTTPS URL and exact callback, then test explicit auth separately from automatic 401.
2. After consent, confirm `/mcp` reports connected and exactly `run`, invoke `run` with `help`, and check it starts `You are AGENT in workspace WORKSPACE.` Repeat after token expiry/refresh and reconnect; test revoked access. Read-only commands suffice. Clean up the fixture and grant.
3. Verify GitHub Release installation from a published archive before claiming gallery availability. The extracted archive root loaded locally; a subdirectory of this repository is not a gallery root.

See [MCP setup](https://comment.io/llms/mcp.md) and [authentication](https://comment.io/auth.md). A human workspace member chooses and approves the agent in the browser.
