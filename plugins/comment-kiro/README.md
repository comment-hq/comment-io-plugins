# Comment.io for Kiro — preparation only

This Agent Plugins package points to the current public remote MCP endpoint `https://comment.io/mcp`, documented as exposing one `run` tool. **It has not been authenticated in Kiro and is not ready for Powers submission.** Agent Plugins v1 `mcp.json` has no portable OAuth configuration field; Kiro must discover and manage client registration or use its host-local OAuth settings. The repository's existing production publication remains pinned to alpha; endpoint reachability does not establish release status.

Before testing with a Client ID Metadata Document (CIMD), the owner must provide a reachable HTTPS document listing the exact fixed local callback Kiro will serve. Configure `oauth.clientMetadataUrl` and a matching `oauth.redirectUri` in Kiro's own MCP settings for this server; do not set `clientId` alongside `clientMetadataUrl`. [Comment.io's authentication contract](https://comment.io/auth.md) now also offers dynamic client registration (DCR) for public clients with no secret or scopes. Kiro documents an automatic DCR attempt when neither client ID nor metadata URL is set, but that flow has not been tested with Comment.io. Agent Plugins v1 `mcp.json` cannot carry host-specific OAuth settings. A human workspace member chooses and approves the agent in the browser. The connected host can receive workspace content; disconnecting ends future access, not content already received.

Kiro's [submission requirements](https://kiro.dev/powers/submit/) require a complete, tested, working package and an MCP service not in beta/preview. On October 8, 2026, the public Comment.io homepage said **“Join the waitlist”** and **“We’re opening access gradually”**; this does not establish eligibility under Kiro's no-beta/preview rule. Current repository artifacts are pinned to alpha. Max must confirm general availability and eligibility before submission. Submission also requires a public repository URL containing `plugin.json`; this package is only a subdirectory and no submission-root arrangement is established. The required submission license field is omitted: the unified repository has no declared GitHub license or root LICENSE, so Max must approve the applicable license and rights before adding it. [Publisher terms](https://kiro.dev/powers/terms/) require Max's explicit approval before acceptance or submission; they include publisher support, at least 90 days of support for existing users after removal, distribution/marketing rights, and indemnification. No terms have been accepted.
