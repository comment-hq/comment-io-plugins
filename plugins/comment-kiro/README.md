# Comment.io for Kiro — preparation only

This Agent Plugins package points to the current public remote MCP endpoint `https://comment.io/mcp`, documented as exposing one `run` tool. **It has not been authenticated in Kiro and is not ready for Powers submission.** Agent Plugins v1 `mcp.json` has no portable OAuth configuration field; installing this package alone cannot supply a client identity. The repository's existing production publication remains pinned to alpha; endpoint reachability does not establish release status.

Before testing, the owner must provide a reachable HTTPS Client ID Metadata Document (CIMD) listing the exact fixed local callback Kiro will serve. Configure `oauth.clientMetadataUrl` and a matching `oauth.redirectUri` in Kiro's own MCP settings for this server; never set `clientId` alongside `clientMetadataUrl` or add a client secret. [Comment.io's authentication contract](https://comment.io/auth.md) requires CIMD, has no dynamic client registration or scopes, and uses a public client without a secret. The generic MCP setup guide assumes the client is already prepared; it does not waive this requirement. A human workspace member chooses and approves the agent in the browser. The connected host can receive workspace content; disconnecting ends future access, not content already received.

Kiro's [submission requirements](https://kiro.dev/powers/submit/) require a complete, tested, working package and an MCP service not in beta/preview. On October 8, 2026, the public Comment.io homepage said **“Join the waitlist”** and **“We’re opening access gradually”**; this does not establish eligibility under Kiro's no-beta/preview rule. Current repository artifacts are pinned to alpha. Max must confirm general availability and eligibility before submission. Submission also requires a public repository URL containing `plugin.json`; this package is only a subdirectory and no submission-root arrangement is established. The required submission license field is omitted: the unified repository has no declared GitHub license or root LICENSE, so Max must approve the applicable license and rights before adding it. [Publisher terms](https://kiro.dev/powers/terms/) require Max's explicit approval before acceptance or submission; they include publisher support, at least 90 days of support for existing users after removal, distribution/marketing rights, and indemnification. No terms have been accepted.
